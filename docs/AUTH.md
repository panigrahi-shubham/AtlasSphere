# SkyAtlas account security contract (Phase 3)

PostgreSQL is the sole account store. `DATABASE_URL` is required for account and saved-journey endpoints; the weather, atlas and anonymous experience remain available without it. Run `npm run prisma:migrate` before production startup; it falls back to `DATABASE_URL` when `DIRECT_DATABASE_URL` is unset. Do not reuse a test database or point tests at production.

- Email is normalized to lowercase and trimmed; responses to password-reset requests are identical for unknown and known accounts. Registration uses 8-128 characters including upper/lowercase letters, a digit and a symbol. Passwords use bcrypt with cost 12; hashes, tokens and reset codes never reach the browser except the access token itself.
- Access tokens are signed HS256 JWTs lasting 15 minutes, kept only in browser memory. `AUTH_SECRET` must be 32+ characters and never bundled. Refresh tokens are random 32-byte values stored as SHA-256 hashes, valid 30 days and rotated at `/api/v1/auth/refresh`. Reuse of a rotated token revokes all sessions belonging to the account. Logout revokes the active refresh token and clears the cookie. Set the refresh cookie HttpOnly, SameSite=Lax, Secure on HTTPS (and production); refresh/logout enforce same-origin browser requests.
- Five failed passwords lock an account for 15 minutes. Account existence is not disclosed in login failure responses. Password reset is limited per IP, uses a six-digit single-use code stored only as a hash, and expires after 10 minutes. The test-only inbox may be read only in `APP_ENV=test`; production reset is disabled unless an email provider is configured. No reset codes are logged or sent in public API responses.
- Users can save at most 20 favorites; user IDs on records are never accepted from clients. Favorites are keyed by a stable city identifier. At login, locally saved places are merged with server places; server entries win duplicate keys and the oldest 20 are retained. Anonymous visitors keep local favorites and theme. Theme sync accepts `light` and `dark` only.
- Every account-owned route requires an access token. Writes validate payloads and authorize based on token user ID. Rate limits complement the API-wide limit. Tests use an isolated PostgreSQL database and unique per-worker accounts; migrations never run on production during test setup.

Environment: `DATABASE_URL`, `AUTH_SECRET`, optional `RESET_EMAIL_PROVIDER_URL`, `RESET_EMAIL_PROVIDER_TOKEN`. If a reset email provider is not configured, production returns an unavailable reset response without revealing whether the account exists. The provider must be HTTPS. Configure HTTPS before offering login publicly.
