# Phases 3–6 implementation and release status

Phase 3 implements Prisma/PostgreSQL, sign-up/in, rotating sessions, reset, synchronized favorites/theme and the security contract in `docs/AUTH.md`. Anonymous usage remains available. The initial migration is applied in local disposable PostgreSQL 18. API integration coverage includes account isolation, replayed refresh revocation, lockout/reset, favorites caps, alert deduplication and review ownership. Browser-level multi-context session-sync coverage remains limited.

Phase 4 adds `/journeys` with historical ERA5 weather (1940 to at least seven days ago), an era slider with correctly labelled scientific context/fiction, saved trips with available-day forecast lookup, in-app weather rules/notifications and landmark reviews with optional validated JPG/PNG up to 2 MB. Production checks alerts about every three hours, limited to 120 rules per pass and at most ten rules per account; matches are deduplicated for 24 hours. The page has no push notifications. Historical data is modelled reanalysis rather than station observations. See [Open-Meteo historical documentation](https://open-meteo.com/en/docs/historical-weather-api) and the [IPCC AR6 synthesis](https://www.ipcc.ch/report/ar6/syr/summary-for-policymakers/).

Phase 5 adds `/test-lab` and per-request fault scenarios in development/test only. In a production build it is absent from `dist`, the API returns 404, and test-only fake inbox data is not registered. See `docs/KNOWN_DEFECTS.md`.

Phase 6 adds Playwright smoke/a11y/lab tests, GitHub Actions with a PostgreSQL 18 service, and `docs/COVERAGE.md`. The Render blueprint expects an existing database URL entered as a secret and generates `AUTH_SECRET`; migration runs before deploy. It creates no database resource. Per-process Open-Meteo quotas stop at 550/minute, 4,500/hour and 9,000/day. Run a single API instance unless a shared quota store is added; process restarts reset these in-memory quotas. Open-Meteo currently restricts the Historical Weather API to Professional or Enterprise and those credentials are not supplied; the Time Machine returns 503 without a server-side `OPEN_METEO_API_KEY`. This is a deployment feature gate, not a verified live integration.

Local verification (27 October 2026): unit tests 48/48; syntax/typecheck pass; PostgreSQL API tests 15/15; Chromium UI 82 passed, 1 intentionally skipped; Firefox and WebKit full regression 160 passed, 2 intentionally skipped, plus the two Journeys UI tests pass in both browsers (4/4); Phase 1–2 production-asset suite 39/39; smoke 2/2; axe 1/1 per browser; Test Lab 9/9; production release 5/5. The separate low-volume live Open-Meteo suite had 10/11 pass on its first run; the one transient invalid-variable request timeout passed on isolated retry. Three mobile Lighthouse runs scored performance 96, 97 and 97, accessibility 100 in every run, and CLS 0, meeting the configured targets. The 9,000/day in-memory guard is deliberately below Open-Meteo's free-tier daily and monthly limits for one service instance, but process restarts reset it. Do not scale the API or run multiple instances without a shared persistent budget. The source is a preview: hosted deployment and GitHub Actions execution are unverified because no Render service, GitHub remote or credentials were available. A live Historical Weather key, reset-email provider and manual contrast review are also outstanding. The production build warns that the optional globe chunk is about 523 kB minified (132 kB gzip).

## Local setup

1. `npm ci`; set a private `DATABASE_URL` and a random `AUTH_SECRET` of at least 32 characters in an ignored `.env` or your shell.
2. Provision a disposable PostgreSQL database and run `npm run prisma:generate && npm run prisma:migrate`.
3. `npm run dev` for the site/API or `npm run build && npm start` for a production build. Open `/journeys`; `/test-lab` works only in development/test.
4. Run `npm test`, `npm run typecheck:api`, `npm run test:api:local`, `npm run test:smoke`, `npm run test:a11y`, `npm run test:ui`, `npm run test:bugs` and `npm run test:release`. Browser tests need Playwright Chromium; `npx playwright install chromium` on a new machine. Never use production data for tests.

The optional local helper `node scripts/test-with-postgres.mjs` uses an actual disposable local PostgreSQL cluster at `.local-postgres/` on port 54329. It needs the Windows/macOS/Linux binary bundled with the `embedded-postgres` development dependency; install scripts must run. This helper never connects to production.

## Before hosting

Provide a dedicated PostgreSQL database and secret URL, ensure HTTPS, configure a server-side reset email provider before offering password reset, and set a server-side `OPEN_METEO_API_KEY` with Professional or Enterprise access before enabling live historical weather. Open-Meteo's free non-commercial API terms currently cap use at 10,000 calls/day, 5,000/hour, 600/minute and 300,000/month; SkyAtlas reserves a lower per-process ceiling of 9,000/day, 4,500/hour and 550/minute. Turn off `FIXTURES` and Test Lab in production. Run migrations and all web release checks before sharing the URL. PostgreSQL hosting and deployment may incur charges; no service was provisioned by this task.
